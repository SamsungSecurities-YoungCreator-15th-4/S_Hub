# 봉인 — 수명주기와 통제 계약

> 이 폴더는 **동결 이후 공개된 감사 증거**입니다. 비공개 자산이 아닙니다.
> PR #140의 `.sealed/` Git 추적 금지 정책은 이 문서로 대체됩니다 (PR #146 리뷰에서 합의).

## 1. 무엇이 들어 있나

| 파일 | 내용 |
|---|---|
| `blind_map.json` | 원본 사례 id ↔ 블라인드 id(B01~B20) 매핑, 배정, 시드 |
| `relabel_map.json` | 재라벨링 3건의 R01~R03 ↔ 사례 매핑 |
| `case-plan.md` | 20건 구성표 — 출제 의도 |

## 2. 수명주기

```
①  설계         출제 의도를 봉인한다. 라벨러·출제자 모두 열지 않는다
②  블라인드 라벨링  사례는 B01~B20으로만 배포. 정답 필드 제거
③  라벨 확정      2인 독립 판정 → 불일치 조정 → 최종 gold label
④  봉인 해제 ★    라벨 확정과 동시에 해제. 이 폴더가 감사 증거가 된다
⑤  동결          `v1-freeze` 태그. 이 시점의 사례·정답이 기준이 된다
⑥  judge v1      동결된 사례·정답을 바꾸지 않은 상태로 1차 판정
⑦  증거 고정      v1 결과와 오류 분석을 기록으로 확정
⑧  judge 개선     ⑦ 이후에만 프롬프트·룰을 손댄다
⑨  judge v2      같은 사례·같은 gold label로 재실행
```

**★ ④가 이 문서의 핵심입니다.** 봉인의 목적은 **블라인드 라벨링을 성립시키는 것**이었고,
라벨이 확정된 순간 그 목적은 끝납니다.

## 3. 해제 이후의 통제 — 비밀유지가 아니라 순서와 해시

동결 후에는 gold label이 `cases/*.md` frontmatter에 **평문으로 공개**됩니다.
따라서 `.sealed/`만 숨겨도 유출 방지 효과가 없습니다. 통제 수단을 바꿉니다.

| 무엇을 증명하나 | 수단 |
|---|---|
| 사람 정답이 judge 실행 **전에** 고정됐다 | `v1-freeze` 태그와 커밋 순서 |
| v1과 v2가 **같은 사례**를 봤다 | `case_hashes.json`의 `case_content_sha256` |
| judge 입력에 정답이 **주입되지 않았다** | 로더 allowlist + `tests/test_goldenset_integrity.py` |
| v1 측정이 judge 개선 **전에** 끝났다 | v1 결과의 커밋 SHA·실행 시각·LangSmith run |

`case_content_sha256`은 **frontmatter를 제외한 본문만** 해시합니다. 정답이 해시에
섞이지 않으므로, 라벨을 바꿔도 해시는 변하지 않습니다(테스트로 고정).

## 4. ⚠️ 발표에서 이렇게 말하지 마세요

> ❌ "정답은 기술적으로 계속 비공개였습니다."

동결 이후 정답은 저장소에 공개돼 있습니다. 사실과 다릅니다.

> ✅ "사람 정답이 judge 실행 전에 고정됐고, judge 입력에는 주입되지 않았습니다."

증명 수단은 태그·해시·로더 테스트이지 비밀유지가 아닙니다.

## 5. R2 담당자에게

judge **실행** 단계에는 gold label이 필요 없습니다. 필요한 것은 실행 후
**일치율을 계산하는 분석 단계**뿐입니다. 저장소에 정답이 있더라도
**실행 로더는 정답 필드를 읽지 않아야** 하며, 이는 테스트로 강제됩니다.

읽어도 되는 frontmatter: `id` · `variant` · `llm_draft`
**읽으면 안 되는 것**: `label` · `fail_axes` · `trap_type` · `rationale` · `labelers` · `initial_agreement`

상세는 `../case-format.md` §0.
