# 정답 사례집 20건 구성표

> `goldenset/labeling-guide.md` v0.1 기준 · **초안 — 팀 검토 후 확정**
> 이 표는 **출제 설계도**다. 실제 `label`·`fail_axes`는 blind 라벨링으로 확정하며, 이 표의 의도와 다를 수 있다.

---

## 0. 이 표의 지위

- 여기 적힌 `의도 label`은 **정답이 아니라 가설**이다. 최종 라벨은 라벨러 2인 이상의 독립 판정으로 정한다.
- 이 파일은 **라벨링 중 열람 금지**다. 본문 작성이 끝나면 `goldenset/.sealed/`로 옮겨 봉인하고, 최종 라벨 확정 **후**에 열어 대조한다 (가이드 §3-6단계).
- 함정을 심었는데 라벨러 둘 다 pass를 줬다면, 그건 라벨러가 못 본 게 아니라 **함정이 안 심긴 것**이다. 본문을 고치거나 pass로 확정한다.

## 4. 본문 작성 시 공통 규격

전 사례 공통으로 지킬 것. **pass 10건은 이 규격을 완전히 지키고, fail 10건은 의도한 함정 외에는 지킨다.**

- 고객: 50대 자영업자, 위탁자산 50억원대, 위험성향 중립, 6자산군
- 기준일: 합성 시계열 최종 영업일로 통일
- **모든 데이터가 합성·가상임을 사례 안에 명시**
- **자기완결적** — judge가 판정에 쓸 입력 수치(§1·§2)와 인용 원문(§4)이 사례 안에 있을 것
- 가상 규정 청크(`internal-rr-*`)는 `goldenset/corpus/`에 두고 judge retrieval 대상에 포함
- LLM으로 초안을 만든 사례는 `llm_draft: true` 표기
- **frontmatter의 `label`·`fail_axes`·`trap_type`·`rationale`은 비워 둔다** (라벨링 후 채움)

### ⚠️ 자충수 방지 — pass 10건 최종 점검

pass 사례가 우리 기준을 어기면 라벨이 pass인데 내용은 fail인 사례가 된다. 작성 후 grep으로 확인한다.

- [ ] `최적`·`최선`·`가장 좋은`·`보장`·`확정`·`반드시`·`무조건`·`절대`·`확실히` — **단순 grep은 오탐이 난다.** 인용문 안(`금지표현-B7`)과 명시적 부정문(`B1`)은 제외하고 판정할 것
- [ ] 근거 없는 "확률 OO%" 0건
- [ ] 출처 없는 외부 사실 수치 0건
- [ ] `E1`(비권유) + `E3`(책임 소재) 둘 다 존재
- [ ] CI 병기본 4건은 `ci_level` 표기가 있고 CI가 점추정치를 품는다
