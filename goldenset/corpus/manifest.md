> ⚠️ **레포 루트의 `corpus/`와 다른 것이다.** 아래 §1 참조.

## 1. `corpus/`와 무엇이 다른가

| | `corpus/` (레포 루트) | `goldenset/corpus/` (여기) |
|---|---|---|
| 목적 | **생성** — 리포트 쓸 때 검색·인용 | **채점 검증** — 인용이 진짜인지 대조 |
| 사용처 | `rag_cite` 노드 (Chroma 인덱싱) | judge 출처 축 · R2 어댑터 |
| 내용 | 실제 PDF 21건 (하우스뷰·거시·세무·방법론) | 우리가 작성한 규정 원문 12건 |
| git | **미포함** (저작권상 로컬 전용) | **포함** |
| `chunk_id` | `methodology_var_cvar_2026.pdf::0003` | `internal-rr-007` |

과제 안내서 R1 각주: *"RAG(생성할 때 검색·인용하는 규정 자료창고)와 다릅니다 — 이것은 채점관을 평가하는 기준지입니다."*

**기존 corpus를 쓸 수 없는 이유**

1. **자기완결성** — 원문 PDF가 gitignore라, 레포를 클론한 사람이 R2를 재현할 수 없다 (가이드 §4 "본문은 자기완결적이어야 한다")
2. **함정 통제** — `case_003`(조항 번호 오류)·`case_018`(인용 조건 생략)은 **정답 원문이 고정돼야** 성립한다. 실제 PDF는 청킹 결과가 실행마다 달라질 수 있다
3. **합성 데이터 원칙** — 사례는 전부 가상이어야 한다

## 2. 실존 / 가상 구분 원칙

`synthetic` 필드로 구분한다. **이 선을 넘지 않는다.**

| 유형 | `synthetic` | 규칙 |
|---|---|---|
| 공공 법령 조문 | `false` | 실존 원문 그대로 인용 가능 (예: 금융소비자보호법) |
| 사내 규정·방법론·하우스뷰·거시·세무 | `true` | **반드시 가상**. 출처명에 `(가상)` 표기 필수 |

### 🚫 하지 않을 것

- **실존 기관명을 붙인 가상 문서 금지.** "삼성증권 2026 채권 전망"이라는 가상 문서를 만들면 실존 기관의 발표를 날조하는 것이 된다 → `사내 하우스뷰(가상)`처럼 익명화한다
- **실존 중앙은행·정부기관의 발표를 지어내지 않는다.** `macro-brief-2026q1-006`은 일반 서술만 담고 특정 기관의 전망을 인용하지 않는다
- **환각 함정(`case_011`)도 실존 기관 발표를 날조하지 않는다.** "한국은행이 인상을 시사했다" 대신 **"입력 데이터에 없는 시장 수치·전망을 출처 없이 서술"**하는 형태로 심는다 — 함정의 성립에는 차이가 없고 위험만 없앤다

현재 12건 중 실존은 `kcfp-art19-001` **1건**뿐이며, 견본 GS-EX-01이 이미 인용한 조문이다.

## 4. 함정과의 연결

일부 청크는 **함정이 성립하기 위해** 존재한다. 지우거나 문구를 바꾸면 해당 함정이 무효가 된다.

| 사례 | 함정 | 의존 청크 | 성립 원리 |
|---|---|---|---|
| `case_003` | 조항 번호만 틀림 | `internal-rr-005` + `internal-rr-007` | 제7조 문장을 **제5조**라 표기 → 두 조문이 모두 있어야 대조로 잡힌다 |
| `case_017` | 10일 CI가 √10 규약 위반 | `method-var-2026-007` | 규약 원문이 있어야 "어긋났다"고 판정 가능 |
| `case_018` | 인용문 조건 생략 | `kcfp-art19-001` | "**및 일반금융소비자가 설명을 요청하는 경우에는**"을 빼고 인용 → 부분문자열 불일치 |
| `case_018` | 없는 규정 인용 | (의도적 부재) | `internal-rr-099`를 인용 → `chunks.json`에 없음 → "존재하지 않는 chunk_id" |

> `app/rag/citations.py`의 `verify_citations()`가 **"인용문이 chunk_id 원문의 실제 부분문자열일 때만 `verified=True`"**로 동작한다. 위 함정들은 전부 이 검증기에 그대로 걸리도록 설계했다.

## 5. 사용 방법

**사례 본문에서 인용할 때** — 견본 GS-EX-01의 §4 형식을 따른다.

```markdown
> "고위험 스트레스 결과는 시나리오 가정과 함께 제시하며, 단일 수치만의 제시를 금지한다."
> — 출처: 사내 리스크리포트 작성기준(가상) 제7조, chunk_id: internal-rr-007
```

**R2 어댑터에서** — `chunks.json`을 읽어 `citations[].extra.chunk_text`를 채운다. 이게 없으면 judge의 출처 축이 검증할 원문을 갖지 못한다.

**청크를 추가할 때**

1. `chunks.json`에 항목 추가 (`synthetic` 필수)
2. §3 목록 갱신
3. 가상이면 출처명에 `(가상)` 표기
4. 이미 라벨링이 끝난 뒤라면 가이드 §4 규칙 갱신 로그에 기록
