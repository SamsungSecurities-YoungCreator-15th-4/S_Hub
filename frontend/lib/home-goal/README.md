# 내 집 마련 Gap

중앙 대시보드의 포트폴리오 아래에 카드 하나를 표시한다. 상세 Dialog에서 고객별
주택 목표를 입력하고 현재/A/B 포트폴리오를 같은 조건으로 비교한다.

- `types.ts`: 원·소수 단위 계산 계약, 만원·% 단위 입력 폼, 명시적 시연 입력.
- `calculateHomeGoal.ts`: 순수 계산, 세 가지 역산, 유효성 검사, 공식 버전·계산 지문.
- `portfolioAdapter.ts`: 입력 단위 변환, 기준 포트폴리오 연결, 판단 보류 문구.
- `homeGoal.test.ts`: 회귀값, 독립 월 적립 계산, 역산, 예외·출처 검증.
- `../../components/home-goal/`: 카드, 상세 Dialog, 전략 카드.

## 계산 가정

사용자 제공 Home Goal 사양의 공식을 따른다. 현재 자금은 `(1+r)^t` 연복리,
월말 저축은 월수익률 `r/12`로 적립한다. 이 두 복리 관례를 단일 연 실효수익률로
통일한 모델은 아니며, 변경 시 공식 버전과 회귀값도 함께 바꿔야 한다.

필요 자기자본은 `max(0, 주택가격 × (1+상승률)^기간 × (1+비용률) − 대출액)`이다.
매수 시점을 연장할 때도 주택가격·부대비용을 다시 계산한다. 목표 시점부터 600개월까지
월 단위로 탐색하며, 찾지 못하면 `null`을 반환한다. 현재 이미 충족했더라도 목표
시점에 다시 부족할 수 있으므로 목표 이전의 일시적 충족을 연장 전략으로 제시하지 않는다.

구매 가능 주택가격은 현재 가격으로 환산한다. 필요한 저축은 만원 단위 올림,
구매 가능 상한은 만원 단위 내림이며, 내부 계산은 반올림 전 숫자를 유지한다.
수익률 0%, 음수 수익률, 즉시 매수, 자기자본 0, 미달성·오버플로를 별도 처리한다.

`computation_hash`는 정렬된 입력·공식 버전·탐색 상한의 FNV-1a 지문이다.
재현성 확인용이며 보안 서명, 승인 증명 또는 충돌 없는 식별자로 사용하지 않는다.

## 연결과 저장

장기 추정은 `basePortfolios.metrics.expectedReturnPct / 100`을 사용한다.
IPS 목표수익률이나 스트레스 후 수익률을 장기 기준으로 사용하지 않는다.
API 기대수익률이 누락되거나 출처가 `fallback/empty`이면 결과를 만들지 않는다.
`demo`만 시연 수익률임을 표시하고 계산한다.

Stress 행은 마지막 분석의 기대수익률 변화(%p)다. 원금 손실률이 아니며 구형 API의
근사치가 포함될 수 있다. 고객별 숫자형 손실허용한도 계약도 없어 적합성은 판단 보류한다.
Gap이 가장 작은 포트폴리오를 계산상 비교하되 자동 추천·거래 승인은 하지 않는다.

입력은 기존 Zustand의 `homeGoalDrafts[customerId]`에 세션 동안만 저장된다.
DB·브라우저 영구 저장은 없으며 새로고침 시 초기화된다. 고객·대시보드 포트폴리오
변경 시 모달과 로컬 비교 선택을 초기화한다. 전체 운용자산과 주택 자금은 독립적이다.

향후 대출 API 또는 정책 엔진은 `expectedMortgageAmount`를 산출해 연결하고,
그 입력의 출처·기준일·가정 조건을 함께 표시하면 된다. 계산 모듈에는 LTV/DSR·세율
정책을 하드코딩하지 않는다. 비용률은 법정 세율이 아닌 사용자 가정이다.
영구 저장이 필요하면 별도 백엔드·Supabase 계약으로 확장하며 `engine/state.py`는 수정하지 않는다.

## 로컬 검증

`frontend/`에서 실행한다. 프로젝트 고정 pnpm 버전은 10.33.0이다.

```sh
pnpm test:home-goal
pnpm lint
pnpm build
NEXT_PUBLIC_DEMO=1 pnpm dev --hostname 127.0.0.1 --port 3000
```

로컬 주소는 `http://127.0.0.1:3000`이다. 기존 시연 로그인 화면에서 로그인 버튼을 누르면
백엔드·Supabase 없이 확인할 수 있다. 운영에서는 `NEXT_PUBLIC_DEMO`를 비워 둔다.
