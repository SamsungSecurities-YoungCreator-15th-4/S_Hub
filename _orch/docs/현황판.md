# S.ymphony Proof 현황판

> 헷갈릴 때 여기부터 보세요. 2026-08-04 기준 · 마감 8/7 · 코드 동결 완료

---

## 1. 이 과제가 뭐였더라

7월에 만든 S.ymphony는 **리포트를 만드는 시스템**이었습니다. 그 안에 `judge`라는 게 있어서 리포트를 채점합니다.

이번 과제는 **"그 judge가 제대로 채점하는지를 증명해라"** 입니다.

방법은 이렇습니다.

```
사람이 정답을 매긴 리포트 20건을 만든다
        ↓
judge에게 채점시킨다
        ↓
사람 정답과 얼마나 맞는지 숫자로 낸다      ← "일치율"
        ↓
틀린 걸 분석해서 judge를 고친다
        ↓
같은 20건으로 다시 재서 전/후를 비교한다
```

여기에 **"불량 리포트는 못 나가게 막기"**, **"증거를 자동으로 남기기"**, **"같은 입력이면 같은 결과 증명하기"**가 붙습니다.

---

## 2. 다섯 덩어리와 담당

| | 뭐 하는 건지 | 담당 |
|---|---|---|
| **R1** | 사람이 정답 매긴 리포트 20건 만들기 | **승민** |
| **R2** | judge에게 채점시키고 일치율 재기 | 지은(계산) · 다경(실행) |
| **R3** | 불량 리포트 못 나가게 막기 | 준호 |
| **R4** | 증거 서류철 자동 생성 | 중현 |
| **R5** | 재현성 + 8/7 모의감사 | 공통 |

**R1이 사슬의 첫 고리입니다.** 20건이 안 나오면 R2가 못 돌고, R2가 안 돌면 R4에 넣을 게 없습니다.
첫 고리는 §6대로 닫혔습니다 — 20건 라벨 확정 후 `v1-freeze` 태그로 동결했습니다.

## 4. 용어 사전

### 채점 관련

**judge** — 우리 시스템 안의 AI 채점관. 리포트를 보고 통과/불합격을 매깁니다.

**6축** — judge가 보는 6개 항목. `출처` `수치 정합` `환각` `위조정밀도` `면책` `금지표현`. **이 여섯 글자를 정확히 써야** 나중에 집계가 안 깨집니다.

**pass / fail** — 리포트 하나에 대한 최종 판정.

**`fail_axes`** — fail일 때 **어느 항목이 틀렸는지** 목록. 1개일 수도 6개일 수도 있습니다.

### 채점 결과 분류

| | 사람 | judge | 뜻 |
|---|---|---|---|
| **미탐** (FN) | fail | pass | judge가 **결함을 놓침** ← 위험한 쪽 |
| **오탐** (FP) | pass | fail | judge가 **멀쩡한 걸 틀렸다고 함** |

과제 안내서가 미탐에만 "(위험)"을 붙였습니다. **둘을 절대 합쳐서 "정확도 85%"로 보고하면 안 됩니다.**

**일치율** — 20건 중 사람과 judge 판정이 같은 건수. `17/20`처럼 분수로 씁니다. (20건은 작아서 1건이 5%p를 움직이므로 소수점 쓰면 안 됨)

### 라벨링 관련

**라벨링** — 리포트 20건에 사람이 pass/fail을 매기는 작업.

**blind** — 정답을 모른 채 판정하는 것. 그래서 사례 ID를 `case_003` 대신 `B07` 같은 걸로 바꿔 배포합니다.

**봉인 (`.sealed/`)** — 어느 사례에 무슨 함정을 심었는지 적어둔 파일. **라벨 확정과 동시에 해제**되며, 그때부터는 감사 증거로 공개합니다. 수명주기는 `goldenset/.sealed/README.md`.

**leakage(누출)** — 정답이 새는 것. 라벨러가 정답을 보면 그 라벨이 무효가 되고, R2 담당자가 보면 정답에 맞춰 judge를 튜닝하게 됩니다.

### ⚠️ 발표에서 조심할 문장

동결 이후 정답은 `cases/*.md`에 **공개돼 있습니다.** 그러니 이렇게 말하면 안 됩니다.

> ❌ "정답은 기술적으로 계속 비공개였습니다."

> ✅ "사람 정답이 judge 실행 **전에** 고정됐고, judge **입력에는 주입되지 않았습니다.**"

증명 수단은 비밀유지가 아니라 셋입니다 — `v1-freeze` **태그**(언제), `case_content_sha256` **해시**(무엇을), **로더 allowlist 테스트**(주입 안 됨).

**recusal(회피)** — 이해충돌이 있는 사람이 스스로 빠지는 것. 지은·다경이 goldenset PR 리뷰에서 빠진 게 이겁니다.

### R2 관련

**v1 / v2** — **judge를 고치기 전 버전이 v1, 후가 v2.** 동시에 도는 게 아니라 개선 전후입니다. 최종 제출에는 v2만 들어갑니다.

**freeze** — "이 시점 코드를 v1으로 못박는다"는 선언. **라벨 확정 시점**을 freeze로 잡기로 했습니다.

**`case_content_sha256`** — 사례 내용의 지문. v1과 v2가 정말 같은 사례를 썼는지 증명하는 용도. 정답 라벨은 일부러 뺐습니다.

**`as_of_date`** — 기준일. v1과 v2를 다른 날짜로 돌리면 비교가 오염되는데, 지금 코드가 안 막고 있어서 나중에 고치기로 했습니다.

### R3~R5 관련

**hard stop** — judge가 끝내 불합격을 주면 **리포트를 확정하지 않고 멈추는 것.** 이게 없으면 과제 무효입니다.

**evidence bundle** — 명령 한 번에 자동으로 만들어지는 증거 서류철. 사람이 스크린샷 모아 만든 건 인정 안 됩니다.

**모의 감사** — 8/7 발표. 심사자가 서류철 1건을 지목하면 **5분 안에 증거 제시 + 3분 안에 재실행**해야 합니다.

## 5. 헷갈리기 쉬운 것 세 가지

**"코퍼스"가 두 개입니다.**

| | `corpus/` | `goldenset/corpus/` |
|---|---|---|
| 용도 | 리포트 **만들 때** 검색 | 인용이 진짜인지 **대조할 때** |
| 내용 | 실제 PDF 21건 | 우리가 쓴 가상 규정 12건 |

**"평가셋"도 두 개입니다.** `tests/`의 `EC-01~20`은 7월에 만든 시스템 테스트용이고, **R1의 20건과는 완전히 별개**입니다.

**"신뢰수준"과 "신뢰구간 수준"도 다릅니다.** 99%는 VaR가 보는 위치, 90%는 그 추정치가 놓일 구간. 섞어 쓰면 그 자체가 함정 소재입니다.

## 6. R1 완료 — 최종 상태

**라벨링이 끝났습니다.** 20건 전부 `cases/*.md` frontmatter에 기입됐습니다.

| | 결과 |
|---|---|
| 최종 라벨 | **pass 10 / fail 10** |
| 사람 간 일치율(IAA) | **18/20** — 라벨 난이도 지표. judge 일치율의 상한이 **아님** |
| 라벨러 | 중현·준호 2인이 전건 독립 라벨. **출제자(승민)는 배제** |
| 6축 커버리지 | 축당 최소 2건 충족 |

라벨링 중에 나온 것들 — 발표에서 쓸 재료입니다.

1. **기준표 빈칸 1개를 잡았습니다.** 반올림 허용 오차가 정의돼 있지 않아 6원 차이를
   한 명은 fail, 한 명은 pass로 봤습니다. 자릿수 유도식(`평가액 × 0.5 × 10⁻ⁿ`)으로 보강했습니다.
2. **출제자 작성 오류 2건을 블라인드 라벨링이 걸러냈습니다.** pass로 설계한 사례에
   진짜 결함이 들어가 있었고, 라벨을 설계에 맞추는 대신 **사례를 고치고 재라벨**했습니다.
3. 이 과정이 전부 `labeling-guide.md` §4와 `goldenset/reports/agreement_before.md`에 남아 있습니다.

## 8. 라벨 확정 후 순서 (나중에 볼 것)

```
1. 답안 3개 → goldenset/labels/
2. python goldenset/tools/score_labels.py --labels goldenset/labels
   → 합의 전 일치율 (이 숫자가 제출물)
3. 불일치 건을 기준표 근거로 조정
4. python goldenset/tools/apply_labels.py --init  → 사람이 채움
5. python goldenset/tools/apply_labels.py --write
6. git commit + git tag v1-freeze   ← 여기가 라벨 동결
7. 그 다음에 judge 실행 (R2)
```

**6번 커밋 전에는 절대 judge를 돌리지 마세요.** 순서가 바뀌면 "judge 보고 라벨 고친 것 아니냐"는 의심을 못 벗습니다.
